how to read this page

While a run trains, it periodically writes a short sample from the same fixed prompts. Each card below is one of those snapshots, newest first, labelled with the training step it came from. Reading them in order shows the model learning: random noise, then common letter clusters, then real words, and finally grammar and the style of your dataset.

This page is optional. It's for watching a run as it trains: if the samples stop improving, or start repeating your training text word for word, the model is overfitting and you can stop the run early. The best checkpoint (lowest validation loss) is kept either way.

ABOUT

NanoGym

what this is

NanoGym is a local web UI and experiment library for training small character-level GPT models on a single machine.

Point it at a text file, launch a run, watch it learn in real time, then generate from the finished model here or export it to run in a web browser.

Source code, issues and updates: github.com/theprint/nanogym

model architecture
  • GPT-style decoder. Token and learned position embeddings feed a stack of pre-LayerNorm transformer blocks. Each block is causal self-attention followed by a GELU MLP (4× expansion), both with residual connections. The output head shares its weights with the token embedding.
  • Character-level. The vocabulary is every character in the dataset plus four special tokens (<pad>, <unk>, <bos>, <eos>), typically around 100–120 symbols, frozen per run in vocab.json. With so few symbols, embeddings are only 1–5% of the parameters. Nearly everything sits in the transformer blocks, which learn how characters combine rather than memorizing word identities.
  • Attention-focused. The design leans on attention to help a tiny model keep context. At character level, a single word spans about five tokens and a sentence about a hundred, so staying coherent means connecting characters that sit far apart. Attention is the only part of the model that moves information between positions. Every preset uses 32-dimensional heads, half the head width of GPT-2, so each layer gets twice as many heads, and each head can track a different kind of look-back (the current word, the start of the sentence, an open quote). The MLPs still hold about twice as many parameters as attention, as in any GPT; the emphasis is on the number of heads.
  • Inspectable. Training uses PyTorch's fused attention for speed. A separate manual path returns the attention weights, which powers the playground's attention heatmap.
  • Training. AdamW (β 0.9/0.95, weight decay on weight matrices only), linear warmup into cosine learning-rate decay, gradient clipping, and mixed precision on CUDA.

tiny trains in minutes, even on a CPU, and is small enough to export and run in a web browser. The ras.ms/prompts generator (prompter-v0.4-Nano) is a tiny model.

small is the default workhorse. It trains quickly on a GPU and picks up spelling and grammar well from a few hundred KB of text.

medium gives the best quality when you have a few MB of text; on smaller datasets it tends to overfit, so watch the train/val gap. occultisms-v2.4 is a medium model.

Parameter counts assume a ~100-character vocabulary and a 256-character context. Context length is set per run, and any preset's layers, width or heads can be overridden in the run's YAML config.
